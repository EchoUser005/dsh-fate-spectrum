# 长期架构

> 本文只描述长期稳定的架构方向、TypeScript 设计判断和演进护栏。当前版本的范围、代码树、TODO 与验收进入活动里程碑；Tool 契约进入 `docs/tool-layer.md`。

## 1. 架构目标

`dsh-fate-spectrum` 在 DeepSeek Harness（DSH）中提供可验证、可追溯、可组合的命理事实能力。

项目沿同一条事实链演进：

```text
时间与命盘事实
  -> 稳定的领域结果
  -> Canonical Tool Result
  -> Agent Observation
  -> Skills / Knowledge
  -> A2UI Presentation
  -> 经授权的 Memory 校准
```

DSH 负责模型、Agent Loop、Session、Tool 调度和应用外壳。本插件不复制这些能力，只在 DSH 边缘注册命理能力。

模型可见 Tool 按独立用户任务拆分，而不是按第三方库或每个原子算法拆分。已确认的长期表面包括：

- 排盘 Tool：接收出生信息，完成民用时／真太阳时处理，返回八字、紫微或两者的命盘事实。
- 干支历 Tool：在后续里程碑中把“下周”“下下周”或明确日期范围解析成可验证的公历、农历与干支时间上下文。

Agent 可以在同一任务中依次调用多个 Tool，再由周报等 Skill 组织分析流程；未来 A2UI 只消费稳定事实和展示投影。一个插件可以注册多个 Tool，但每个 Tool 仍只有一个清晰任务和一个任务级 Executor。

长期架构的目标不是提前设计所有未来模块，而是确保新能力加入时：

- 确定性事实不被模型推测替代。
- 第三方库和 DSH 变化不污染稳定领域。
- 工程结果、模型 Observation 和 UI 数据不混用。
- 用户状态、计算约定和 Provider 状态不发生跨调用污染。
- 复杂性只随真实变化轴增长。

## 2. 稳定边界

```text
DSH Agent
  |-> Fate Chart Tool -> FateChartExecutor
  |                     |-> Birth Time Correction
  |                     |-> Bazi / Ziwei Engines -> Providers
  |
  \-> Ganzhi Calendar Tool -> GanzhiCalendarExecutor -> Calendar Range Engine

Canonical Results -> Observations -> Skills -> Presentation DTO / A2UI
```

### Domain

表达时间、出生信息、命盘事实、计算约定、来源信息和可预期领域失败。

- 不依赖 DSH、Cordis、React、第三方命理库、网络、数据库或 Session。
- 不出现 Provider 专属对象、模型文案或 UI 坐标。
- 领域值优先使用不可变数据和判别联合。

### Task Executor

一个模型可见 Tool 对应一个任务级 Executor。Executor 编排一次完整产品操作：

- 校验和归一化边界输入。
- 解析并冻结本次调用的计算约定。
- 根据 Tool 参数路由到一个或多个原子计算引擎。
- 组合成功、部分成功和可修复失败。
- 生成经过验证的 canonical result。

Task Executor 不实现历法算法，不读取 DSH Session，也不生成 DSH ContentBlock。它可以持有通过依赖注入获得的引擎，但不得持有某个命主或某次调用的可变状态。

### Atomic Capability Engines

原子计算引擎承载可独立定义、测试和复用的业务计算能力，例如出生时刻校准、八字、紫微、干支时间范围和未来干支作用。

- 引擎输入和输出使用本项目的领域类型，不使用模型参数对象或第三方对象。
- 八字与紫微各自拥有独立引擎；共享一个排盘 Executor 不代表合并两套计算实现。
- 引擎只负责本能力内部的计算与不变量，不决定另一套系统是否执行，也不组合 Tool 顶层状态。
- 出现第二个真实消费者前，不把引擎拆成独立 Package 或服务。

### Providers

第三方库、离线算法和外部数据源的防腐层。

- 每个独立计算体系拥有独立端口和 Adapter；Provider 是引擎背后的实现边界，不是第二个任务级 Executor。
- 第三方类型、异常、全局设置和隐藏默认值不得越过 Provider。
- Provider 只返回领域结果，不直接生成 Tool Observation。
- Provider 升级不能直接改变公共 Tool 契约。

### DSH Adapter

只负责 DSH/Cordis 生命周期、Tool 注册、Schema 接入、取消信号和结果交付。

- 不修改或复制 Agent Loop。
- 不在 Adapter 内实现命理规则。
- DSH import 不进入任务级 Executor、原子计算引擎或 Domain。
- 注册、监听和资源占用必须随 Cordis 生命周期可逆地释放。

### Projections

同一 canonical result 可以投影给不同消费者：

- Observation 面向 Agent，说明本次发生了什么和下一步如何行动。
- Presentation DTO 面向 UI，表达怎样稳定重放和渲染。
- 开发诊断面向工程，不得进入模型或用户数据。

投影层不得重新计算、改变错误分类或查询隐式状态。

## 3. TypeScript 边界纪律

### 3.1 类型与运行时校验

- 所有外部值先视为 `unknown`，经过运行时 Schema 校验和 Adapter 映射后才能进入任务级 Executor。
- Schema 与 TypeScript 类型保持单一来源，优先从 Schema 推导类型。
- 禁止用类型断言掩盖未校验的第三方数据。
- 对 Provider 输出再次执行运行时不变量校验，不能因为依赖有类型声明就直接信任。
- 可序列化公共值只使用明确的 JSON 数据结构。

### 3.2 封闭状态

成功、部分成功、需澄清、不支持等有限状态使用带稳定判别字段的联合类型。

- 每个分支必须可穷尽检查。
- 新增状态时让编译器暴露所有未处理消费者。
- 可预期领域失败作为值返回；程序缺陷、不变量破坏和非预期基础设施异常才抛出。
- 不使用布尔字段组合出无法解释的隐式状态。

### 3.3 不可变调用快照

一次调用开始时完成输入归一化和约定解析，形成只读快照。

- Provider 执行期间不得重新读取会变化的默认配置。
- 时间、时区、经纬度、流派、换日和算法版本必须来自同一快照。
- 同一输入、版本和约定应产生可重复的领域结果。

### 3.4 纯函数优先

- 计算规则、映射、校验和 Projection 优先使用无副作用纯函数。
- 数据默认使用 `readonly`，更新时创建新值。
- 只有对象确实拥有生命周期、资源或必须共同维护的不变量时才使用 class。
- 异步只存在于真实异步边界；纯计算函数不因上层异步而被包装成无意义的异步函数。
- `AbortSignal` 从 DSH 边缘贯穿所有可能耗时或可取消的调用。

## 4. 抽象、复用与目录开启条件

默认从具名函数和领域内聚模块开始。目录是变化边界的结果，不是预先画好的组织装饰。设计模式和新目录都必须由真实问题触发，不能因为“以后可能会用”而预建。

| 设计选择         | 适用触发条件                                 | 不应使用的情况               |
| ---------------- | -------------------------------------------- | ---------------------------- |
| 领域内具名函数   | 单一规则、单一消费者或纯转换                 | 不要先放入通用 `utils`       |
| 共享函数/模块    | 已出现第二个真实消费者，且语义和变化原因一致 | 仅代码形状相似、业务含义不同 |
| 任务级 Executor  | 一个 Tool 需要编排多个步骤、能力或失败分支   | 单一原子函数可以直接完成     |
| 原子能力目录     | 能力有独立输入输出、不变量和验收证据         | 只有一个字段映射或展示格式   |
| Port / Adapter   | 外部依赖需要隔离，或已经存在可替换实现       | 对每个内部函数都创建接口     |
| Strategy         | 已存在两种真实算法、流派或可替换政策         | 只有一个实现和一个默认值     |
| Factory          | 多种对象组合、构造规则或生命周期确实不同     | 只包装一个构造函数           |
| State Machine    | 存在明确状态、非法转移、恢复或取消路径       | 简单同步计算或少量独立布尔值 |
| Observer / Event | 多个独立消费者需要响应同一稳定事件           | 单一调用链可以直接返回结果   |
| Projection 目录  | 同一事实出现模型、UI 等两个不同消费者        | 只有一个返回格式             |
| class            | 需要封装生命周期、资源或跨方法不变量         | 纯数据、纯计算和 DTO 映射    |
| 独立 Package     | 出现独立运行时、发布节奏或客户端消费者       | 仅为了目录看起来整齐         |

开新目录前必须能回答三个问题：它保护哪个业务边界、谁是它的消费者、它为什么会与相邻代码以不同原因变化。三个问题任一没有答案，就先留在现有内聚模块中。当前版本的精确目录树只写入活动 develop 技术方案，不进入长期架构。

禁止：

- 用 Singleton 保存命主、生日、命盘、当前调用或可变 Provider 配置。
- 建立没有真实消费者的抽象基类、注册表或扩展系统。
- 让一个 `utils` 目录承接无法归类的业务逻辑。
- 因一次复用就把领域语义抹平成通用参数。

## 5. DSH 与 Cordis 组合规则

项目复用 DSH 的 Agent Loop 和 Cordis 组件系统，不建立第二套运行时。

- Tool、Prompt Section、未来 UI 节点和其他注册必须通过官方扩展点。
- 每个 Effect 都必须有明确清理路径；卸载后不得残留监听器、服务或 Tool。
- 依赖服务通过 Cordis 注入，不从模块全局查找。
- 依赖缺失时按官方生命周期保持未激活或返回明确装配失败，不做隐式降级。
- 只消费 DSH 服务并注册 Tool 时优先使用函数插件；只有向其他插件提供有生命周期的 Service 时才引入 class 形式。
- 并发能力采用 fail-closed 默认：没有隔离证据就视为不安全。
- DSH 处于快速演进阶段；涉及其 API 时必须核验锁定版本的官方源码和文档。

## 6. Provider 与计算约定

不同命理体系和时间算法保持独立演进：

- `FateChartExecutor` 负责排盘任务；出生时刻校准只服务排盘，由它在内部编排，不注册独立模型 Tool。
- 后续干支历 Tool 拥有自己的 `GanzhiCalendarExecutor`，负责把相对或绝对时间范围变成公历、农历、节气和干支上下文；它不接收出生信息，也不承担命盘计算。
- 八字、紫微、出生时刻校准、干支历和未来干支作用各自保持独立原子引擎；出现语义完全一致的第二个消费者后才提取共享实现。
- Provider 负责适配第三方实现，原子引擎负责本能力的领域输入输出，两者不得被统称为多个 Tool Executor。
- 共享输入通过稳定领域值传递，不通过第三方对象共享。
- 计算默认值在 Executor 进入原子引擎前解析完成。
- 流派、换日、太阳时、闰月和算法版本随结果披露。
- 依赖存在模块级可变状态时，用实例隔离、调用级快照或保守串行控制；未经测试不得宣称并发安全。
- Provider 探针和差分证据先于公共契约冻结。

## 7. 渐进披露

渐进披露发生在稳定事实之后，不靠模型从长文本中猜重点。

```text
Rich Domain Result
  -> Canonical Result
  -> requested sections
  -> concise Observation
```

- Canonical result 保留程序化消费者所需的稳定事实。
- Observation 只包含当前请求相关事实、约定、警告和下一步。
- 模型需要更多事实时，通过稳定 section 再次请求，不依赖隐式缓存。
- Prompt Section 只放长期调用纪律，不放动态命盘、用户档案或大段案例。
- UI 使用独立 Presentation DTO；不得解析 Observation 文本还原命盘。

未来引入 A2UI 时：

- 使用稳定 ID 和可重放 Session Event。
- Whole-value Checkpoint 足以恢复 UI。
- 全局命盘和局部 Focus 使用同一事实来源。
- UI 事件和模型文本都不能成为计算真值。
- 大运／流年长期走势、一年内周期曲线和关键时间窗口等可视化，只消费命盘、干支历与干支作用的稳定事实；曲线纵轴、聚合规则和“高低”含义必须先形成可审核的计算契约，不能让组件或模型临场编造分数。
- 当第一个可交付可视化用例、稳定 Presentation DTO 和目标 DSH A2UI 接口同时确认后，才开启独立展示组件目录；组件、主题资产和交互事件不得反向进入命盘计算引擎。

## 8. Knowledge、Skills 与 Memory

- Skills 定义跨 Tool 的分析流程，不实现确定性命盘或干支历计算。例如周报 Skill 可以指导 Agent 先取得时间范围上下文，再取得命盘事实，最后完成分析与展示。
- Knowledge 保存获得许可的共享规则、格局和案例材料。
- Memory 只保存用户授权的个人事实、反馈和已确认结果。
- 模型推测未经用户确认不得进入 Memory。
- Knowledge、Memory 和命盘计算保持独立生命周期与数据策略。

未来 Skill 需要 A2UI 时，只能消费 canonical result 或专用 Presentation DTO，不得从 Observation 文本反解析命盘和干支历。Agent 根据“长期走势”“今年曲线”“比较某段运势”等用户意图选择展示组件；Skill 负责分析流程，组件负责可视表达，两者都不能改写命盘事实。具体曲线语义、组件输入输出、事件和渲染能力在 A2UI 里程碑核验 DSH 官方接口后再设计。

这些能力优先使用成熟的 DSH 扩展点；除非生态能力无法满足已确认需求，不自建数据库、RAG、Memory 或第二套 Agent 系统。

## 9. 状态、隐私与并发

- 每次计算接收完整输入，不读取“当前用户”或“最近命盘”。
- 用户数据不进入进程级缓存、模块级变量或普通日志。
- DSH Session 的数据保留行为必须如实披露，插件不额外创建副本。
- 未来持久化、缓存或 UI 事件必须先完成作用域、版本、删除和跨用户隔离设计。
- 生日数据即使哈希也不自动视为匿名数据。
- 所有公开测试只使用人工构造案例。

## 10. 架构变化规则

出现以下变化时才修改本文，并先获得用户确认：

- 稳定层级、依赖方向或运行时所有权改变。
- 引入新的长期能力类别或独立运行时。
- 改变 TypeScript 边界校验、状态表达或复用原则。
- 引入数据库、缓存、Memory、RAG、自定义 UI、Python 服务或第二个 Agent Loop。
- DSH/Cordis 的官方模型迫使生命周期或组合方式改变。

版本功能范围和验收节点属于活动里程碑；精确文件树、文件职责、实现顺序和分层测试属于活动 develop 技术方案；Provider 选择、公共契约和发布 Gate 分别进入 ADR、Tool 专项文档或开发流程。这些当前实现信息不进入本文。
