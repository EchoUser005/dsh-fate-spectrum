## 1. 目的

验证 v0.1.0 需要的紫微基础事实能否通过 iztro 稳定映射，并检查未知时辰、闰月、安星流派、重复确定性与模块级配置隔离。全部探针使用人工构造数据，不包含真实用户生辰。

## 2. 版本、许可证与维护状态

- `2.5.8` 是官方 GitHub Releases 与 `CHANGELOG.md` 当前最后有发布说明的版本，修复了中州派晚子时人盘问题。
- npm 安装器已提示 `2.6.0` 可用，且官方主分支 `package.json` 已是 `2.6.0`；但官方 Release 与变更记录尚未提供对应发布说明。首版因此保守锁定 `2.5.8`，不把未审计的差异带入 Provider。

- 2025 至 2026 年持续增加中州派并修正闰月、晚子时与宫位计算，可视为仍在维护。

## 3. 已验证能力

已知公历／农历日期、时辰与性别时，iztro 可以离线映射：

- 公历、农历、干支日期与时辰范围；
- 命宫、身宫、命主、身主和五行局；
- 恰好十二宫的宫名、宫干支和身宫标记；
- 主星、辅星、杂耀的名称、类型、亮度、四化与作用范围；
- 每宫大限的起止虚岁和干支。

同一合成输入重复 20 次只产生一份结果。一份命盘满足十二宫、唯一命宫和唯一身宫的基础不变量。

## 4. 未知时辰证据

iztro 使用 `0..12` 表示早子、丑、寅……亥、晚子十三个时辰槽。合成日期的十三个时辰槽生成十三份不同命盘；时段连续覆盖全天：

```text
00:00–01:00 早子  |  01:00–03:00 丑  | … | 21:00–23:00 亥
23:00–24:00 晚子
```

因此可以落实用户已确认的候选语义：

- 已知时分只返回所属时辰槽的一份命盘；
- 未知时辰返回覆盖全天的十三份候选命盘，每份显式携带适用时段；
- 不猜测某个时辰，也不把候选语义误标成系统失败；
- Observation 要求模型提取候选的共同事实，差异部分按时辰条件解读。

## 5. 已冻结的决策

### 5.1 安星流派

iztro 同时支持：

- `default`：以《紫微斗数全书》为基础的通行安星法；
- `zhongzhou`：中州派安星法。

同一合成命盘的命宫与五行局未变，但命主从“破军”变为“廉贞”，整份命盘指纹不同。首版默认 `standard`，并开放 `zhongzhou` 显式选择。

### 5.2 闰月安宫

iztro 同时支持：

- `fixLeap = true`：闰月十五日（含）前仍按本月，十五日后按下月安宫；
- `fixLeap = false`：整个闰月都按当月安宫。

合成闰二月二十日在两种规则下使用同一公历日期，但命宫／五行局分别为“寅宫／水二局”和“丑宫／金四局”。首版默认 `split_at_day_15`，并开放 `whole_leap_month` 显式选择。

## 6. 共享状态约束

iztro 的安星流派、年／运限／小限分界、晚子时、四化和亮度是模块级配置。正式 Provider 必须：

1. 调用前保存配置快照；
2. 使用本次已解析的显式约定计算；
3. 持有共享配置时不产生异步让出；
4. 在 `finally` 中恢复原配置；
5. A/B/A 与跨命主隔离测试通过前不声称并发安全。

第三方对象、方法、翻译 key 和异常不得越过 Provider 边界。

## 7. 探针后的正式决定

- 精确锁定 `iztro@2.5.8`；默认通行安星法，显式支持中州派。
- 默认闰月十五日分界，显式支持整个闰月按本月安宫。
- 四化与亮度首版使用 iztro 2.5.8 自带数据，不接受自定义表；未来开放其他派别时必须单独审核。
- 未知出生时辰返回十三份时辰槽候选；宫位和星曜使用本项目定义的稳定 ID。
- 只验证原局与大限；流年、流月、流日、流时和命理解读不属于本切片。

完整决定见 [ADR 0014](../project/decisions/0014-ziwei-v0-1-contract-and-defaults.md)。
