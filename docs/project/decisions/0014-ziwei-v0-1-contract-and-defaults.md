# ADR 0014：紫微首版契约与默认规则

- 状态：已接受
- 日期：2026-08-16

## 背景

iztro 2.5.8 探针证明，安星流派、闰月安宫和未知出生时辰都会改变紫微命盘。它还使用模块级配置；如果调用后不恢复，连续为不同命主或不同流派排盘时可能串状态。首版需要在真实 Provider 接入前冻结默认值、显式选项、候选语义和稳定输出身份。

## 决定

1. 紫微 Provider 精确锁定 `iztro@2.5.8`。该版本有官方 Release／Changelog 证据并使用 MIT 许可证；不追随缺少独立发布说明的版本。
2. 安星流派默认使用以《紫微斗数全书》为基础的通行安星法，对外值为 `standard`；模型可显式选择 `zhongzhou`。
3. 闰月默认采用十五日分界，对外值为 `split_at_day_15`：十五日（含）前按本月、十五日后按下月安宫；模型可显式选择 `whole_leap_month`，让整个闰月按本月安宫。
4. 四化和星曜亮度首版固定使用 `iztro@2.5.8` 自带表，不在 Tool Schema 中开放自定义表。未来引入其他派别或自定义规则必须重新审核。
5. 已知出生时辰返回一份紫微命盘。未知出生时辰不猜测、不分配概率，返回 iztro 的早子、丑至亥、晚子共十三个时辰槽候选，并标注每份候选适用时段；Agent 可分析共同事实，对差异作条件式解读。
6. 每份候选返回十二宫、命身宫锚点、命主身主、五行局、星曜、亮度、四化和大限。宫位使用稳定英文 ID；命宫和身宫锚点同时携带宫位 ID、宫干和宫支。星曜 ID 由宫位、类型和规范中文名组合，不依赖数组下标。
7. Provider 每次调用建立只读规则快照，在同步临界区设置 iztro 配置，并在 `finally` 恢复调用前的全部相关标量设置。未证明并发安全前，不声明紫微 Provider 可并发执行。
8. 紫微结果披露 Provider 版本、默认或显式规则来源，以及固定的换日、年界、运限与虚岁边界。第三方对象不得越过 Provider 防腐层。

## 影响

- 默认双系统请求可以同时返回真实八字与真实紫微命盘；仅紫微请求也能独立成功。
- 模型能看到明确流派与闰月规则，不会把某一派的结果误写成唯一算法真相。
- 未知时辰会增加输出体积，但保留了真实不确定性，也为后续 A2UI 候选切换留下稳定数据。
- 未来升级 iztro、改变流派默认、开放自定义四化／亮度或压缩候选，都属于公共契约变化，必须先复审探针和 Schema。

## 不包含

- 不在本决定中实现真太阳时地点解析、干支时间范围 Tool、命理解读、周报 Skill 或 A2UI。
- 不根据用户经历自动反推时辰。
- 不把十三份候选误标为顶层 `partial`；它们属于一个成功紫微结果内部的条件集合。
