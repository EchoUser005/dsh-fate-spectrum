# ADR 0013：未知出生时辰返回完整候选盘

- 状态：已接受
- 日期：2026-08-16

## 背景

Tyme 1.5.2 探针证明，未知时辰不等于“只缺时柱”。默认 23 点换日会让同一民用日期出现不同日柱；节气交接日还可能出现不同年柱、月柱、日主、十神、起运和大运序列。把未知时辰固定成 `00:00`，或只删除一个任意单盘的时柱，都会制造错误事实。

用户希望 Agent 在不伪造确定性的前提下继续使用能算出的信息：共同事实直接分析，不同候选按条件分别解读。

## 决定

1. `birth.time = { status: "unknown" }` 仍是合法排盘输入，不自动转成 `needs_clarification`。
2. 八字 Provider 枚举出生日期内 `00:00` 至 `23:59` 的全部民用分钟，并按真正影响模型分析的离散命盘事实压缩候选：年／月／日柱、日主、柱内十神事实、起运顺逆、大运干支、交运年份和周岁范围。
3. 每个候选必须列出其适用的一个或多个出生时间范围；所有范围合计必须恰好覆盖全天 1440 分钟，不能遗漏或重复。
4. 未知时辰候选只返回年、月、日三柱；时柱、时柱藏干／十神／纳音／旬空／十二长生和所有依赖时柱的作用事实一律不生成。
5. 精确交运时刻随分钟连续变化，不制造 1440 个仅交运分钟不同的候选。每个离散候选返回其适用时段内最早与最晚交运时刻，并保留大运的离散年份和周岁范围。
6. 顶层 `partial` 只表示多系统请求中某系统成功、另一系统发生可安全分类的失败。未知时辰存在多个合法候选不是系统失败，八字系统仍返回 `success`。
7. Observation 必须明确区分共同事实与候选事实，要求模型作条件式解读，不得替用户擅自选择一个候选。

## 影响

- 用户不知道时辰时仍可得到诚实、可用的受限命盘，而不是被拒绝或收到伪单盘。
- 节气日、晚子时和起运边界不会被静默吞掉。
- Provider 计算量增加，但当前离线合成测试证明全日枚举可在可接受时间内完成；后续只能在不改变候选集合的前提下优化。
- 完整视太阳时接入后，候选枚举必须基于校准后的实际排盘时间重新验证，不能直接复用民用时假设。

## 不包含

- 不根据现实经历反推或自动锁定某个时辰。
- 不返回时柱的“概率”、猜测或默认值。
- 不在本决定中实现干支作用、紫微未知时辰或真太阳时算法。
