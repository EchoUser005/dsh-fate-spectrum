# ADR 0007：GitHub 协作与 CI 合并策略

- 状态：已接受
- 确认日期：2026-08-16

## 背景

仓库需要让所有变更都经过可见 PR 和稳定 CI，同时保持个人维护效率。外部贡献不能因为测试通过就自动进入主分支，仓库所有者自己的已授权改动则不应反复手工点击合并。

## 决定

- `main` 只通过 PR 更新，要求线性历史、解决全部审查对话，并禁止强制推送和删除。
- CI 固定执行所有者合并策略、Node.js `24.19.0` 完整质量门禁和 Node.js `22.19.0` 最低兼容门禁。
- 所有者发起的 PR 自动满足合并策略；其他作者必须先获得 `owner-approved` 标签。
- 仓库启用 auto-merge，但只有具备写权限的人可以开启；日常 PR 采用 squash merge，并在合并后删除分支。
- 当前不要求审批数量。外部贡献由 `owner-approved` 门禁表达所有者的明确审核，避免个人仓库无法审批自己 PR 的死锁。
- Tag、GitHub Release 和 npm 发布不接入自动化，仍需用户对当次发布明确授权。

## 影响

CI 通过只证明工程门禁通过，不替代产品、架构和发布授权。若以后向其他人授予仓库写权限，必须重新评审 auto-merge 权限边界和审批规则，因为写权限成员也能够开启自动合并。
