# ADR 0005：README 的用户定位

- 状态：已接受
- 确认日期：2026-08-16

## 决定

- README 的主要读者是插件使用者，不是仓库开发者。
- README 介绍插件使命、使用方式、长期愿景、版本能力、核心技术信念、隐私和使用边界。
- README 可以用简短、人话的方式解释“程序计算事实、Agent 负责理解与推理”的设计信念，但不展开内部模块、依赖版本、测试 gate 或架构炫技。
- README 不记录 Phase、仓库完成度、测试结果或下一开发步骤。
- 用户可见能力、安装方式、用法、版本、限制或隐私发生变化时必须评审 README；内部重构、依赖升级和测试变化不自动触发文案更新。
- 版本能力必须和实际发布边界一致；长期规划可以表达方向，但不得伪装成已经上线。
- README 的变更记录是面向使用者的产品版本摘要，每个版本只写一句；不得链接或复制开发过程的 `docs/project/CHANGELOG.md`。
- README 的核心技术只陈述实际机制及其作用，禁止加入自我评价、口号或不增加信息的总结句。
- 用户已经提供产品原文时，README 编辑应以整理结构、修正逻辑和压缩重复为主，不得把原文降级成灵感参考后重新创作；有明确业务含义的术语应优先保留。
- 开发状态只写入 `docs/project/PROJECT_STATE.md`；技术细节进入专项文档。

## 影响

README 必须像项目自己在说话，而不是开发报告。每次修改都要先回答：命主会因此更清楚它能陪自己做什么吗？
