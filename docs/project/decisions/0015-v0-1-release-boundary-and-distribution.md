# ADR 0015：v0.1.0 发布边界与分发入口

- 状态：已接受
- 日期：2026-08-16

## 背景

用户已经在真实 DSH 对话中验证八字、紫微、默认双盘、结构化补问和未知时辰候选能够支持高质量分析。当前缺口不再是排盘主链，而是把开发态 `--patch` 变成其他 DSH 用户可以稳定获取的正式 Bundle。

完整视太阳时仍需要离线地点解析、经度修正、均时差依据和跨日行为的独立审核。它不应为了赶首个版本而使用不完整算法，也不应阻塞已经验收的民用时排盘能力公开发布。

## 决定

1. `v0.1.0` 的公开能力边界是民用时下的八字、紫微、默认双盘与未知时辰候选；完整视太阳时校准移入后续独立切片，不在本版伪装成已实现能力。
2. Tool 继续保留显式时间模式；请求尚未实现的完整视太阳时时，返回可识别的 `unsupported`，不静默退回民用时。
3. npm 预构建 Bundle 是普通用户的推荐安装入口，包名使用 `dsh-fate-spectrum`。用户通过 `dsh plugin --profile web add dsh-fate-spectrum@0.1.0` 安装。
4. tarball 与 npm 使用同一份预构建内容，作为本地、离线安装和发布候选证据；`--patch` 只用于源码开发。
5. GitHub 源码直装不作为首版推荐入口。它需要安装时执行 `prepare`，pnpm 会要求用户额外授权构建脚本。
6. package 版本和 canonical `schemaVersion` 同步提升为 `0.1.0`；字段、状态、错误语义和 Observation 不随此次提升改变。

## 影响

- README 必须优先展示 npm 安装，本地 tarball 次之，不把开发态 Patch 命令放在普通用户主路径。
- 发布物必须包含预构建 `lib/`、`cordis.patch.yml`、Bundle manifest、README、许可证和第三方声明；不得包含源码开发资料、真实生日或 `.local/`。
- 发布前必须把实际 tarball 安装进隔离 DSH Profile，验证 Bundle 自动入列、组合配置和 Web 启动。
- 真太阳时进入后续里程碑时，仍遵守 ADR 0011 的“先校准、后换日”顺序；本决定只调整版本交付范围，不改变未来算法约束。
- push、Tag、GitHub Release 和 npm 发布仍需当次明确授权。
