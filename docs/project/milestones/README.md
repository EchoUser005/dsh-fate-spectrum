# 里程碑管理

里程碑文档跨越多轮 iteration，承载一个可发布版本的用户功能目标、范围、验收节点、决策门和完成证据。精确代码树、文件职责和实现顺序进入里程碑链接的 `docs/develop/` 技术方案。

## 活动规则

- 同一时间只能有一个活动里程碑。
- `PROJECT_STATE.md` 必须直接链接活动里程碑和当前 iteration。
- 每轮开始时读取活动里程碑；只更新本轮实际推进的条目和证据。
- 任何新增范围或公共行为都先展示里程碑 diff；目录职责和实现方案变化展示对应 develop 技术方案 diff，由用户确认后再实现。
- 长期架构和 Tool 契约只通过链接引用，不在里程碑中复制第二份真相源。

## 完成与归档

里程碑全部达到完成定义后：

1. 冻结最终范围、勾选状态、验证证据和已知限制。
2. 用户确认该里程碑完成。
3. 将文档移动到 `archive/`，保留版本号和历史链接。
4. 冻结该版本的 develop 技术方案，并移动到 `docs/develop/archive/` 的对应版本目录。
5. 最终 iteration 记录验收、归档和遗留项。
6. `PROJECT_STATE.md` 清除旧活动里程碑并指向下一阶段。
7. README 只在用户可见能力通过发布审核时更新。

归档不等于发布。Tag、Release、push 和 npm 发布仍需用户当次明确授权。
