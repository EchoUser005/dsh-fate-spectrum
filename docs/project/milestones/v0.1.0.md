## 1. 版本结果

用户在 DSH 对话中提出排盘或命理分析需求后，Agent 能补问必要出生信息，调用本版的 `calculate_fate_chart`，取得可靠的八字、紫微或双系统命盘事实，再继续分析。

v0.1.0 交付的是命盘底图，不交付命理解读体系。它必须让用户真实完成一次从自然语言请求、信息补齐、Tool 调用到模型使用命盘事实继续回答的完整流程。

## 2. 本版用户能力

- 用户未指定系统时，一次请求同时取得四柱八字与紫微斗数命盘。
- 用户明确指定时，只计算八字或只计算紫微。
- Tool 返回八字原局、起运与大运等本版确认的基础命盘事实。
- Tool 返回紫微十二宫、命身宫、星曜、四化、五行局与大限等本版确认的基础命盘事实。
- 本版使用明确时区下的民用出生时间排盘，并披露实际采用的时间模式与计算约定。
- 出生时辰未知时保持明确未知，返回覆盖全天的合法候选盘及适用时段；不生成时柱或时柱相关事实。
- 输入可修复时，Agent 能根据结果继续追问并用完整参数重试。
- 同时请求两套系统时，一套成功、另一套发生可安全分类的独立计算失败，保留可信结果并明确返回 `partial`。

## 3. 已确认行为

- v0.1.0 只交付排盘 Tool `calculate_fate_chart`；这不是插件长期只能注册一个 Tool，后续干支历 Tool 在独立里程碑交付。
- `systems` 可以请求八字、紫微或两者；省略时默认同时计算。
- 八字与紫微分别计算、分别报告结果；统一入口不能让两套命盘事实互相污染。
- v0.1.0 的模型参数不暴露 `name`、`relation`；它们不影响计算事实，未来经授权的 Memory 场景再单独设计。
- 八字使用民用时排盘，再按 23:00 换用次日日柱；允许显式选择晚子时仍算当天。完整视太阳时进入后续切片，显式请求时不得静默退回民用时。
- 八字起运默认采用 `lunar_sect_1`；结果必须披露默认或显式规则来源。
- 紫微默认采用通行安星法 `standard`，可显式选择 `zhongzhou`；闰月默认 `split_at_day_15`，可显式选择 `whole_leap_month`。
- 紫微四化与亮度首版固定使用 `iztro@2.5.8` 内置规则；未知时辰返回早子至晚子十三份候选盘。
- 共享输入问题和可修复领域失败返回 canonical outcome。
- 只有输出不变量破坏、程序缺陷或非预期基础设施异常向 DSH 抛出。
- Tool 运行时不访问 LLM、第三方排盘网站、在线地理编码、数据库或缓存。
- 公共测试和文档示例只使用人工构造数据。

公共参数、canonical result、错误码和 Observation 行动语义只以 `docs/tool-layer.md` 及用户后续确认的契约 diff 为准。

## 4. 本版不包含

- 命理解读、吉凶结论、人生建议或第三方断语。
- 原局与大运、流年、流月、流日、时辰之间的完整干支作用引擎。
- Weekly Skill、案例 Knowledge/RAG 或用户 Memory。
- 自定义命盘 UI、A2UI 或 Focus 点击分析。
- 插件自有数据库、缓存、用户系统、Python/FastAPI 服务或第二个 Agent Loop。
- 干支时间范围 Tool；它的长期独立边界已经确认，但名称、Schema 和实现进入后续里程碑。
- 完整视太阳时的地点解析、经度修正、均时差与跨日校准；本版只交付民用时排盘。

## 6. 用户决策门

出现以下任一情况立即暂停，在本文件说明影响与候选方案后等待用户决定：

- Tool Schema、canonical result、错误语义或 Observation 行动变化。
- 未知时辰能够返回哪些八字或紫微字段。
- 未知时辰、太阳时地点精度、闰月或紫微流派默认值；已确认的 23 点换日、起运、通行安星法和闰月十五日分界如需改变也必须重新审核。
- 所选计算依赖的能力、许可证或维护状态与本版目标不一致。
- DSH 官方 API 与技术方案不一致。
- 需要使用真实生日、网络服务或持久化数据验证。
- 想在本里程碑提前实现后续干支历 Tool，或新增计划外 Tool、UI、Memory、RAG、服务、数据库、缓存、Python、第二个 Agent Loop。

## 7. 完成定义

v0.1.0 只有同时满足以下条件才可标记完成：

- 用户能在真实 DSH 对话中完成一次自然语言排盘流程。
- 默认双系统和两个显式单系统请求都返回经过验证的命盘事实。
- 八字与紫微分别计算；默认双系统与显式单系统选择正确，调用之间不串状态。
- 民用时间模式和计算约定可追溯，未知值没有被猜测填充；未实现的完整视太阳时没有被伪装成成功。
- canonical outcome、`partial`、Observation 和异常边界符合用户冻结的契约。
- 断网可计算，公开仓库、CI 与发布物不包含真实生日或私人规划。
- 实际 tarball 可安装并通过锁定 DSH 版本的 Profile smoke。
- 未实现能力没有用占位假数据、空壳 Tool 或模型猜测伪装完成。
- 用户完成最终验收并同意归档。

## 8. 用户如何审核

日常只需要先看本文件：

- 用户能得到的能力是否仍是本版统一排盘目标；是否把后续干支历 Tool 或周报 Skill 提前塞入本里程碑。
- 是否出现计划外功能或降低完成标准。
- 八字、紫微和时间能力是否在实现前安排了用户输入输出审核。
- 未决默认值是否真的在编码前停下。
- 勾选项是否有真实证据。

需要审核“代码准备怎样组织”时，再进入本文件顶部链接的 develop 技术方案；需要审核模型参数、结果或错误时，再进入 Tool 契约。这样里程碑保持可读，技术细节也不会失去明确归属。
