# README 产品表达复审

日期：2026-08-16

## 本轮目标

让 README 沿用用户原始需求中的情感和业务愿景，建立可持续更新的产品表达结构，不再使用机械的产品说明语气。

## 实际改动

- 以“每个人都希望活成自己命盘最好的样子”为全文精神起点。
- 建立定义与愿景、长期规划、使用指南、版本更新、核心技术、隐私与许可结构。
- 使用指南不虚构成熟案例，只保留经真实体验逐步补充的入口和方向。
- 将核心技术压缩为“程序计算事实，Agent 负责理解与推理”的用户可理解表达。
- 同步 README 定位 ADR、AGENTS 阅读路由、开发流程、项目状态和变更记录。

## 验证要求

- 运行文档格式检查、链接检查、私有内容扫描和 `git diff --check`。
- 审核 README 不包含 Phase、仓库完成度、测试结果、依赖版本或下一开发步骤。

## 遗留项

- 使用案例等待真实测试中出现后，由用户选择并补充。
- 版本能力仍需在正式发布前按实际验收结果复核。

## 用户复审修正

- README 产品版本记录与开发变更记录完全分离；每个产品版本只保留一句使用者可理解的摘要。
- 删除核心技术中的口号、自我评价和无信息量总结，只保留实际设计机制。
- 使用指南按用户要求只保留 `[待补充]`，等待真实测试案例。
- 未来能力恢复原始需求中的准确含义，包括受控的命盘视觉交互规则、组件、资产和变量，以及真实因果记忆和干支作用象意实例化。
- `AGENTS.md` 增加 README 分栏目更新触发表；README 产品版本史与每轮一句的开发变更摘要彻底分离。
