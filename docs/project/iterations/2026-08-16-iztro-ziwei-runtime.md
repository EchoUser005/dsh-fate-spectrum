# 迭代：iztro 紫微运行时与双系统成功链路

- 日期：2026-08-16
- 分支：`feat/tool-skeleton`
- 目标：把已审核紫微字段接入真实 iztro Provider，并让默认双系统和显式紫微请求返回可验证命盘事实

## 用户确认

- 精确锁定 `iztro@2.5.8`。
- 通行安星法为默认，保留中州派显式选项。
- 闰月默认十五日分界，保留整个闰月按本月安宫的显式选项。
- 未知时辰返回早子至晚子十三份候选盘，不猜测唯一时辰。
- 四化与亮度首版使用 iztro 自带规则；稳定宫位／星曜身份由本项目定义。

## 改动

- 增加独立 `IztroZiweiProvider`、Provider-backed 紫微原子引擎和 composition root 组装；`FateChartExecutor` 仍只负责任务路由与 outcome 组合。
- 将十二宫、命身宫锚点、命主身主、五行局、星曜、亮度、四化和大限映射为不含第三方对象的领域模型。
- 已知时辰返回一个候选；未知时辰返回覆盖全天的十三个时辰槽候选，并保留早子／晚子差异。
- 在同步临界区按调用设置 iztro 流派与闰月规则，并在 `finally` 恢复原配置。
- Tool output 升至 `0.1.0-dev.3`：默认双系统和显式紫微均可返回真实 `success`；安全 Provider 失败仍保留既有 `partial` 语义。
- Observation 展开命盘规则、命身宫锚点、四化、十二宫、星曜亮度和大限；未知时辰要求按候选条件式分析。
- 新增 ADR 0014，并同步 Tool 契约、技术方案、里程碑、人工测试 SOP、第三方声明和项目状态。

## 测试证据

- Provider contract tests 覆盖已知时辰字段、未知时辰十三候选、通行／中州 A/B/A 恢复、两种闰月规则差异和非法闰月修复语义。
- DSH contract tests 覆盖默认双系统、显式紫微约定、紫微 Observation 和 output schema 校验。
- 全仓 27 项测试通过；类型检查与构建通过；合成十三候选的紫微 Observation 为 11,470 字符，并以 `< 15,000` 契约限制失控膨胀。
- Node.js 22.19.0 下 `pnpm run dsh:prepare` 成功，隔离 `DSH_HOME` 的 `--patch --dump-config` 出现 `fate-spectrum -> lib/index.js`。
- 隔离 DSH Web Profile 使用新构建在 `127.0.0.1:3092` 启动并返回 `200 OK`，验证后已关闭。
