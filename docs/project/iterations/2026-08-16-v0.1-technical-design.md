# 迭代记录：v0.1.0 技术方案与文档披露层级

- 日期：2026-08-16
- 分支：`docs/v0.1-technical-design`
- 状态：已由用户反馈扩展；后续见 `2026-08-16-tool-skeleton.md`

## 目标

把长期架构、版本功能里程碑和当前开发技术方案彻底分层，并修正旧的“双 Executor”表述，让用户能够先审核业务目标，再按需下钻到 TypeScript 文件职责和实现流水线。

## 实际改动

- 长期架构增加任务级 Executor、原子计算引擎与按需开启目录的判断原则，不记录当前文件树。
- v0.1.0 里程碑删除技术基线和代码树，只保留用户能力、验收节点、决策门与完成定义。
- 新增 develop 文档层和 `calculate_fate_chart` v0.1.0 详细技术方案。
- 明确一个 `FateChartExecutor` 编排独立八字、紫微和时间引擎，Provider 只负责第三方适配。
- 用 Moya registry／Executor／ToolResult 类比 DSH `defineTool`／Executor／`output.render()`。
- 更新 `AGENTS.md` 阅读路由、Tool 层流程、ADR 和归档规则。
- 保留用户补充的 Cordis 论文官方入口。

## 只读参考边界
